# 몰입 퀘스트 — Python 학습·클래스룸 첫 버전

Status: ready-for-agent

전체 제품 방향과 Testing Decisions의 주 검증 경계는 사용자 확인을 받았다. to-spec 절차에 따라 로컬 작업 기록에 게시한 구현 준비 명세다.

## Problem Statement

강사는 별도로 작성한 프로그래밍 수업을 학생에게 배정하고, 학생이 무엇을 풀었는지와 제출한 코드·테스트 결과를 한곳에서 확인하고 싶다. 학생은 자신의 컴퓨터에서 실제 코드와 개발 도구를 사용하며 학습하고 싶다. 앱 운영자가 학생들의 AI 실행 비용을 부담하는 구조를 피하고, 학생이 준비한 AI 환경을 사용해야 한다.

수업 콘텐츠는 앱과 독립적으로 작성할 수 있어야 한다. 학습 과정, 코드 작성, 실행과 AI 사용이 앱 안에서 연결되어야 하며 강사는 중앙에 모인 기록으로 진도를 파악해야 한다.

## Solution

Rust와 Dioxus로 Windows/macOS용 설치형 앱을 제공한다. 첫 버전의 학습 언어는 Python이다. 앱은 상시 인터넷 연결을 필요로 하며, 학습 프로그램과 테스트는 학생 컴퓨터에서 실행한다.

강사는 클래스룸을 만들고 가입 링크를 발급한다. 로그인한 학생이 링크를 통해 클래스룸에 참여하면 강사가 배정한 수업을 볼 수 있다. 수업은 챕터와 단원으로 구성되며 학생은 앱 안에서 Python 코드를 작성하거나 지정된 빈칸을 채우고 테스트를 실행한다. 기본 검사는 입력·예상 출력 비교이며 복잡한 검사에는 작성자 정의 Python 검사 코드를 사용한다.

사용자는 자신의 AI 도구를 준비하고 앱에 연결한다. AI는 설명·힌트 제공과 코드 수정·실행을 모두 지원한다. 앱은 설치 안내를 제공하고, 사용자 대신 AI 도구를 설치하는 기능은 제공하지 않는다. 사용자의 연결 권한·사용량 조건을 이용하며 특정 유료 모델의 무료 이용을 보장하지 않는다.

중앙 서버는 학생별 진도, 테스트 결과, 제출 시점의 코드를 저장한다. 강사는 자신의 클래스룸에 참여한 학생의 기록을 확인한다. 강사와 관리자 모두 수업을 작성할 수 있고 공개 수업 은행에 제공한다. 수업은 작성자만 수정할 수 있으며 복사 기능은 없다.

## User Stories

1. 학생으로서 Windows 또는 macOS에 앱을 설치하여 내 컴퓨터에서 학습하고 싶다.
2. 학생으로서 서비스에 로그인하여 내 참여 클래스룸과 기록을 구분하고 싶다.
3. 강사로서 클래스룸을 생성하여 학생들을 그룹으로 관리하고 싶다.
4. 강사로서 클래스룸 가입 링크를 발급하여 학생을 초대하고 싶다.
5. 학생으로서 가입 링크로 클래스룸에 참여하여 배정된 수업을 보고 싶다.
6. 학생으로서 로그인 전 가입 링크를 열어도 로그인 후 해당 클래스룸 참여 흐름을 이어가고 싶다.
7. 강사로서 클래스룸의 학생 목록을 확인하여 참여 인원을 알고 싶다.
8. 강사로서 수업 은행에서 공개 수업을 선택하여 클래스룸에 배정하고 싶다.
9. 학생으로서 클래스룸에 배정된 수업 목록을 확인하여 학습할 내용을 찾고 싶다.
10. 강사로서 수업을 작성하여 앱을 변경하지 않고 새 콘텐츠를 제공하고 싶다.
11. 관리자로서 수업을 작성하여 공통 콘텐츠를 제공하고 싶다.
12. 수업 작성자로서 챕터와 단원을 순서대로 구성하여 학습 내용을 체계적으로 묶고 싶다.
13. 수업 작성자로서 단원 설명과 기본 코드를 제공하여 학생의 학습을 안내하고 싶다.
14. 수업 작성자로서 코드 작성 문제를 제공하여 학생이 직접 프로그램을 만들도록 하고 싶다.
15. 수업 작성자로서 수정 가능한 빈칸을 지정하여 입문 학생의 과제 범위를 줄이고 싶다.
16. 학생으로서 빈칸 문제에서 지정된 부분만 편집하여 제공된 코드 구조를 유지하고 싶다.
17. 학생으로서 수업·챕터·단원 목차를 탐색하여 현재 학습 위치를 알고 싶다.
18. 학생으로서 앱 내부에서 Python 코드를 편집하여 과제를 수행하고 싶다.
19. 학생으로서 내 컴퓨터의 Python 실행 환경을 사용하여 프로그램을 실행하고 싶다.
20. 학생으로서 앱에서 실행 출력과 오류를 확인하여 문제를 수정하고 싶다.
21. 수업 작성자로서 입력값과 예상 출력값을 등록하여 기본 입출력 문제를 검사하고 싶다.
22. 수업 작성자로서 Python 검사 코드를 제공하여 입출력 비교로 표현하기 어려운 과제를 검사하고 싶다.
23. 학생으로서 앱 내부에서 단원의 테스트를 실행하여 통과 여부를 확인하고 싶다.
24. 학생으로서 테스트 실패와 실행 실패를 구분하여 원인을 파악하고 싶다.
25. 학생으로서 테스트를 통과하여 해당 단원의 완료 상태를 얻고 싶다.
26. 학생으로서 제출 시점의 코드와 테스트 결과를 서버에 기록하여 강사가 내 작업을 확인하도록 하고 싶다.
27. 학생으로서 중앙 저장 실패 여부를 확인하여 제출이 기록됐는지 알고 싶다.
28. 학생으로서 수업과 챕터의 진도를 확인하여 남은 학습량을 알고 싶다.
29. 강사로서 학생별·수업별 진도를 확인하여 학습 현황을 파악하고 싶다.
30. 강사로서 학생의 제출 코드와 테스트 결과를 확인하여 수행 내용을 이해하고 싶다.
31. 학생으로서 내 AI 도구의 준비 방법을 안내받아 연결하고 싶다.
32. 학생으로서 앱 안에서 AI의 설명과 힌트를 받아 학습을 이어가고 싶다.
33. 학생으로서 연결한 AI가 코드를 수정하고 실행할 수 있도록 하여 AI를 활용하는 과제도 수행하고 싶다.
34. 강사로서 다른 작성자의 공개 수업을 배정하여 공용 콘텐츠를 활용하고 싶다.
35. 수업 작성자로서 내 수업만 수정하여 콘텐츠의 책임과 소유 관계를 유지하고 싶다.
36. 수업 작성자로서 같은 수업에 수정 내용을 반영하여 별도의 수업이 늘어나지 않도록 하고 싶다.
37. 학생과 강사로서 단원 추가·삭제 후 현재 구성에 맞는 진도율을 확인하고 싶다.
38. 학생으로서 문구 수정 후에도 기존 단원 완료 상태를 유지하고 싶다.
39. 수업 작성자로서 다시 풀어야 하는 변경을 표시하여 학생이 수정된 과제를 다시 수행하도록 하고 싶다.
40. 학생과 강사로서 본질적 변경으로 완료가 취소되어도 이전 제출 기록을 확인하고 싶다.
41. 학생으로서 서비스 사용에 인터넷 연결이 필요함을 알고 중앙 기록에 연결된 상태에서 학습하고 싶다.
42. 서비스 운영자로서 첫 운영에서는 지정된 한 명에게만 강사 권한을 제공하여 일반 학생의 클래스룸·수업 생성을 제한하고 싶다.

## Implementation Decisions

- 학생용 화면과 강사·관리자 기능을 Rust + Dioxus 기반 앱에서 제공하며 역할 권한은 서버에서도 검사한다. 첫 운영의 강사는 사용자 본인 한 명이며 일반 가입자가 강사 권한을 선택하는 흐름은 제공하지 않는다.
- Rust 서버가 로그인, 클래스룸 참여, 수업 배정, 콘텐츠, 진도와 제출 기록을 관리한다. 학생 앱에 중앙 DB 접속 자격 증명을 배포하지 않는다.
- 학생 앱은 SQLite를 로컬 저장에 사용한다. 서버의 배포 DB는 Supabase의 PostgreSQL을 사용하며 Supabase의 기타 제품 기능에 의존하는 구성을 요구하지 않는다. 인증 제공 방식은 구현 시 결정한다.
- 서버의 주요 관계는 사용자 역할, 클래스룸, 클래스룸 참여, 가입 초대, 수업 작성자, 챕터, 단원, 클래스룸 수업 배정, 학생 진도, 제출과 테스트 결과다. 접근 권한은 역할뿐 아니라 해당 클래스룸 참여·운영 관계로 확인한다.
- 수업은 앱과 독립적인 콘텐츠 형식으로 저장하고 배포한다. 현재 JSON 수업 로딩은 참고 가능한 기존 경계이며 최종 작성 UI와 저장 형식은 구현 선택이다.
- 단원은 코드 작성 문제와 고정 템플릿의 지정 빈칸 문제를 지원한다. 완성된 프로그램을 실행·검사하고 그 제출물을 저장한다. AI 수정 기능에서도 빈칸 밖의 고정 코드는 보호한다.
- Rust 실행 관리 계층이 학생 컴퓨터의 Python 프로세스를 실행하고 입출력 및 오류·종료 상태를 수집한다. 기본 검사는 데이터로 정의하며 작성자 정의 Python 검사에는 별도 실행 계약을 둔다. 출력 비교 규칙, 실행 시간·출력량 제한과 검사 코드의 인터페이스는 구현 시 명시한다.
- Python 실행 환경이 없거나 AI 도구 연결이 불가능한 경우 정상 테스트 통과와 구분하여 준비 안내·오류를 표시한다. 언어 도구 설치 자동화는 이번 명세의 필수 기능이 아니다.
- 실행과 테스트는 학생 자원을 사용하고 진도·제출·검사 결과는 중앙 기록한다. 로컬 검사 결과를 서버가 독립적으로 재검증한 결과로 표현하지 않는다. 서버에서의 재채점은 이번 범위에 포함하지 않는다.
- 단원 완료는 테스트 통과를 기준으로 처리한다. 수동 완료 버튼은 현재 데모에만 존재하며 최종 학습 흐름의 완료 판정으로 사용하지 않는다. 실제 제출과 결과 저장을 사용자가 확인할 수 있어야 한다.
- 공개 수업은 작성자만 수정할 수 있고 관리자 역할 자체가 타인의 콘텐츠 수정 권한을 주지 않는다. 수업 복사 기능을 제공하지 않는다.
- 수정 시 수업의 식별자는 유지한다. 내부 검사·제출 기록에 필요한 변경 식별자는 별도 새 수업으로 노출하지 않는다.
- 단원 추가·삭제 후 현재 단원으로 진도를 재집계한다. 삭제된 단원의 과거 제출 기록은 보존하며 현재 집계에서 제외한다. 안정된 단원 식별자를 사용한다.
- 작성자는 단원 수정 시 다시 풀어야 하는 변경 여부를 표시한다. 문구 수정은 완료를 유지하고 해당 표시가 있는 변경은 영향을 받는 단원의 완료를 취소한다. 이전 제출과 테스트 결과를 보존하며, 변경 전 콘텐츠에 대한 늦은 제출이 변경 후 완료를 회복하지 않도록 한다.
- AI 연결 계층은 설명·힌트와 코드 수정·실행을 지원하며 사용자 환경의 도구·권한을 이용한다. 제공자별 차이는 해당 계층에서 처리하고 연결 실패를 명확히 표시한다. 모든 LLM이 오프라인 로컬 모델이어야 한다는 요구는 없다.
- 사용자 후속 지시에 따라 첫 기본 연결은 설치된 Claude Code CLI 호출이다. CLI에서 설명·힌트 또는 수정 코드를 받아 앱에 반영하고 실제 Python 실행·검사는 앱의 로컬 실행 관리 계층을 사용한다. OpenAI 호환 연결은 선택적 대체 경로다.
- 서비스는 항상 온라인이다. 오프라인 학습·오프라인 제출 대기열은 구현하지 않는다. 코드 초안의 로컬 보존은 오프라인 서비스 제공과 구분한다.

## Testing Decisions

### 확정된 주 검증 경계

학생과 강사가 사용하는 학습 흐름의 외부 동작을 가장 높은 경계에서 검증한다. 대표 시나리오는 강사의 수업 작성·배정 → 로그인한 학생의 가입 링크 참여 → 앱 내부 Python 편집·테스트 → 중앙 제출 기록 → 강사의 진도·코드 확인이다. 사용자가 이 경계를 확인했다.

### 검증 원칙과 범위

- 좋은 테스트는 버튼이나 API로 시작한 동작의 사용자 결과를 검사한다. 내부 함수 호출 순서, SQL 문장 문자열, UI 구현 구조를 복제하지 않는다.
- 학습·제출 흐름은 실제 작은 Python 프로그램과 임시 작업 공간을 사용한다. 성공·오답·실행 오류·시간 초과를 구분하고 중앙에 저장된 코드와 결과가 실행한 제출물에 대응하는지 확인한다.
- 빈칸 문제는 지정 영역만 수정 가능한지, 합성된 프로그램이 검사되고 제출되는지 확인한다.
- 클래스룸 권한은 학생의 강사 기능 접근, 다른 클래스룸 기록 열람, 타인의 수업 수정 요청을 거부하는지를 확인한다. 반복 가입은 중복 참여 기록을 만들지 않아야 한다.
- 진도는 학생·클래스룸·수업별로 분리되어야 하며 중복 제출로 완료 단원 수가 늘어나지 않아야 한다.
- 수업 수정 검증은 문구 수정, 단원 추가·삭제, 본질적 변경의 완료 취소, 과거 제출 보존과 오래된 결과의 늦은 도착을 포함한다.
- PostgreSQL 서버 경계에서 배정·제출·진도·권한 저장을 통합 검증한다. SQLite 데모 테스트를 PostgreSQL 호환성의 증거로 사용하지 않는다.
- AI 계층에서는 제어 가능한 대체 연결로 힌트·수정·실행 동작과 오류 처리를 검증하고, 지원 제공자의 실제 연결은 별도 연동 확인으로 다룬다.
- Windows와 macOS에서 앱 빌드, Python 프로세스 실행과 경로 처리를 각각 검증한다. 한 OS의 통과를 다른 OS의 검증으로 보고하지 않는다.
- 온라인 저장 실패를 성공한 제출로 표시하지 않으며 연결 실패와 검사 실패를 구분한다.

### 기존 검증 사례

현재 로컬 데모는 SQLite 재열기 후 진도 유지, 중복 완료, 학생·클래스룸·수업 간 분리, 완료 취소, 존재하지 않는 단원 거부, 중복 단원 ID와 삭제 단원의 집계 제외를 검사한다. 수업 파싱과 진도 저장 경계는 재사용하되 새 학습·중앙 제출 흐름에서 관찰 가능한 결과를 우선한다. 현재 두 테스트는 Windows 환경에서 통과했으며 데스크톱 화면의 수동 검증과 macOS 검증은 아직 수행하지 않았다.
